# Methodology

This document states exactly what QuantVol computes, so results can be audited.

## 1. Timing and look-ahead

Bars are daily. A strategy sees data up to and including the close of bar `t` and emits a target
weight `w[t]` in `[0, 1]`. The engine holds that weight during bar `t + lag` (`lag >= 1`,
default 1), so the position that earns the return of bar `t` was decided at the close of bar
`t - lag`. Configuring `lag = 0` raises an error.

Everything that feeds a signal is causal:

* **Regimes** use a trailing rolling window of log returns ending at `t`; warm-up bars default
  to the medium regime instead of being back-filled.
* **Indicators** (SMAs, realized volatility) use trailing `rolling()` windows only.

`tests/test_lookahead.py` enforces this by corrupting every price after bar *t* and asserting
that regimes, signals and equity up to *t* are unchanged.

## 2. Volatility regimes

```
vol[t]  = std(log(P[t-k+1..t] / P[t-k..t-1])) * sqrt(252)        (k = vol_window)
regime  = 0 (low)    if vol <  low_thresh
          1 (medium) if low_thresh <= vol < high_thresh
          2 (high)   if vol >= high_thresh
```

Thresholds are asset-specific. The SPY config uses 10% / 20%; the synthetic config uses
14% / 25%. They were set from domain knowledge (typical equity-index realized volatility) before
looking at results, not fitted to them.

## 3. Strategies

| Strategy | Rule |
|---|---|
| Regime-filtered crossover | `w = 1` if `SMA(fast) > SMA(slow)` and the regime is not in `flat_regimes`, else `0` |
| Volatility targeting | `w = 1[P > SMA(m)] * min(1, target_vol / realized_vol)`; `0` until volatility is computable |

Both are long-only and unleveraged (`w <= 1`).

## 4. Cost model

Each bar pays `|w[t] - w[t-1]| * (commission_rate + slippage_rate)` as a deduction from that
bar's return (the first position counts as turnover from zero). The buy-and-hold benchmark pays
the same entry cost once, so strategy and benchmark are compared net of the same friction.
Costs are proportional; there is no market-impact or financing model (see limitations).

## 5. Metrics

| Metric | Definition |
|---|---|
| Total Return | `E[T] / E[0] - 1` |
| CAGR | `(E[T] / E[0]) ^ (252 / n_bars) - 1` |
| Sharpe | `(mean(r) - rf/252) / std(r) * sqrt(252)` (sample std) |
| Sortino | same numerator over the root-mean-square of negative excess returns |
| Max Drawdown | `min(E / cummax(E) - 1)` |
| Calmar | `CAGR / abs(MaxDD)` |
| VaR / CVaR 95% | 5th percentile of daily returns / mean of returns at or below it (historical) |
| Exposure / Turnover | mean `abs(w)` / sum of `abs(dw)` per year |

Per-regime attribution groups each bar's return by the regime known at the **prior close**
(the state in which the position was actually held). Sharpe is reported as undefined (`NaN`)
when annualized volatility in a bucket is below 0.5%, which happens when the book is flat.

## 6. Stress scenarios

Signals and regimes are **recomputed on the shocked price path**, so adaptive logic is tested,
not just a fixed position under duress.

| Scenario | Shock |
|---|---|
| Vol spike | Scale deviations of daily returns around their mean by a factor |
| Flash crash | One-day price drop at a chosen bar that persists afterwards |
| Cost surge | Commission and slippage multiplied (default 5x) on the unshocked path |

The engine is an immutable dataclass; the cost scenario runs on a modified copy.

## 7. Walk-forward validation

For each fold, the `(fast, slow)` pair with the best **in-sample** Sharpe over `train_days` is
selected, then traded on the next `test_days` bars. Out-of-sample returns from all folds are
stitched together. Indicators are warmed up on earlier history, but no bar after the fold's
end influences it (`tests/test_stress_walkforward.py` perturbs later data and checks that earlier
folds are unchanged). This estimates how the *selection procedure* performs, rather than how the
single best in-sample parameter set did.

## 8. Data

* **Real:** SPY daily bars 2005-01-03 to 2024-12-30 from Yahoo Finance (`auto_adjust=True`, so
  prices are split and dividend adjusted), bundled at `data/sample/spy_2005_2024.csv` for offline
  reproducibility. Provided for demonstration; check the vendor's terms before redistributing.
* **Synthetic:** a Markov-switching GBM with three regimes (`quantvol.data.synthetic`),
  deterministic per seed. Used as a test fixture and to demonstrate mechanics. Because the data
  was generated by a regime model, results on it say nothing about live performance.

## 9. Known limitations

* Daily close-to-close execution; no intraday fills, partial fills, or market impact.
* Proportional costs only; no borrow, financing, taxes or capacity constraints.
* Single-asset, long-only; no portfolio construction or shorting.
* The bundled sample is one instrument over one 20-year window that was dominated by a bull
  market. Conclusions about the strategies should be read in that light.
* Parameters in `configs/spy.yaml` are reasonable defaults, not an optimized set. The sweep and
  walk-forward outputs show how sensitive results are to that choice.
